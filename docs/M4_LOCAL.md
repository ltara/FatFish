# M4 本机独立使用与审批验收

2026-10-25，Windows。当前工作区，未提交；**不是整个 M4/M5 完成声明**。

## 产品路径

用户澄清“不接 QQ 也要能用”。新安装默认 `channels.qq.enabled = false`，基础告知后即可进入软件；Key 未配置时可先进入设置，不强制扫码。QQ 接入留在设置：单独告知账号风险、明确确认，再启动后台、登录和配对。关闭渠道保留绑定，不影响本机对话。

旧配置没有该字段但已配置 URL/主人时，兼容保留原渠道行为；显式 false 始终优先。配置更改由 Core 串行原子写入，保留绑定和其他字段；损坏配置不被覆盖。未接入时不探测端口、不启动后台或对外引擎，也不报“QQ 掉线”。

## 本机对话与审批

- Main/preload/renderer 完整接线，顶层主窗口鉴权；其他窗口不能发起本机任务或作出审批。对话仍只进 local，对外渠道不能选择它。
- 当前按完整消息展示，非流式；支持安全的段落、行内代码、代码块和列表。模型 HTML 仅作为文本，图片不加载；链接只复制，不打开浏览器。
- `chat/` 保存最多 400 条当前展示记录及历次会话文件，新开对话不删除旧会话；引擎原生会话持久化仍在 `dsh/local/sessions`。`chat/stats.json` 只含本机计数，不因新开会话清零。首页区分本机和远程统计范围。
- 审批沿用 rc2 **内置** `tools/pre-execute` → ask → ApprovalService；保留内置拒绝/询问，不自建权限系统。因默认策略放行工作区操作，本机插件对原本 allow 的工具调用也返回 ask。工作区写入现已实际验证允许、拒绝和超时，不再沿用“工作区内不问”的旧 UI 口径。
- 卡片显示工具操作、目标文件名、可展开的实际参数；仅“允许这一次 / 不允许”，无永久授权。120 秒到期拒绝；Core 根据权威 deadline 拦截迟到答案，UI 不决定超时授权。
- 审批会唤起最小化窗口，首页与原生托盘提示等待确认；记录结论不代表操作必然成功，实际结果仍由工具返回。
- rc2 stdio SDK 没有 cancel 方法，因此停止本机回复通过停止 local 实例完成，不虚构 RPC；下一次按需重启并恢复会话。超时也停止实例，避免 UI 结束后后台工具继续运行。

## 独立 UX 走查

独立执行者 `/root/local_ux_review` 未看源码/设计/历史，只通过 Windows 原生窗口完成首页 → 对话 → 输入 → Enter 发送 → 等待 → 收到回复，在 800×560 复查主要区域。报告与 3 张原生图在同级 `fatfish-m4-local-3/ux/`。

发现首页“已暂停 / 未暂停”范围不明确，已改为本机/远程分别展示真实计数和中性字段名，由主 Agent 重新跑功能检查。测试模型只回复固定文字，不能因此认定正式模型内容质量缺陷。独立走查没有验证审批、真实模型或真实 QQ；这些不能冒充已独立验收。

供走查保持窗口的 `--review` 会话最后退出码为 1，出现 Chromium accessibility 的 NOTREACHED 诊断，未取得足以确认退出原因的证据；同类诊断也出现在退出码 0 的功能回归中，不能据此断言为产品崩溃根因。该保持窗口会话不作为绿色回归命令，功能结论取上述明确退出 0 的测试。
