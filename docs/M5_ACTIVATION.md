## 1. 本轮交付

`activation-server/` 是独立服务端项目，不进入现有 Electron `files` / `extraResources`。

- `src/worker.mjs`：`POST /activate`、管理导入/查询/精确解绑/作废，严格字段、固定错误分类、16KB 请求上限、IP 哈希限流、无 CORS。
- `schema.sql`：码哈希、设备哈希与限流表。设备容量和 active 状态由一条原子 SQL 写语句同时检查，默认最多 2 台。
- Ed25519 私钥只在 Worker secret；许可证签名覆盖原始 payload 字节，没有过期时间。坏签名配置在分配名额之前失败。
- 激活码批量生成、服务端密钥/管理令牌生成、受控管理 CLI；均不在命令行回显私钥/令牌/发货明文。
- 本地 Node >=22，Wrangler 锁定 `4.152.0`；不改变客户端锁定依赖、vendor Node 或引擎版本。
- `.dev.vars`、`.wrangler` 与 `.local` 已忽略；正式私钥没有生成/写入仓库。

操作方法、签名格式、密钥备份/恢复和生产准备清单见 `activation-server/README.md`。

## 3. 必须明确的产品边界

**永久离线许可证不能被服务端远程撤销。** 作废/解绑只改变未来签发与设备名额，不能让已经离线激活的旧设备立即停用。测试明确保留原签名仍有效，不把这点伪报为失败或实时防盗版能力。若产品改为在线吊销，就会违反当前永久离线约定，需另做产品决策。

限流只限制同来源 IP，不解决分布式滥用；上线仍需 WAF、费用限制与告警。本地 health 只是 HTTP 存活，不能当成数据库和签名健康。生产 D1 ID/域名/secrets 均未配置；本地通过不代表线上已生效。
