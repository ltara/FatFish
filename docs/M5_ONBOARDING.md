## 1. 两条独立流程

- 基础流程：激活（1/4）→ 基础风险告知（2/4）→ 保存模型和 Key、显式测试连接（3/4）→ 在正常对话页自己发一句并收到成功回复（4/4）。不安装、不启用、不登录 QQ 也能完成。
- 完成本机流程后才提供可选 QQ：单独确认账号风险（1/4）→ 登录小号（2/4）→ 主人配对（3/4）→ 主号实际试聊并收到正常模型回复（4/4）。默认不启用，不代替用户勾选。
- 「稍后设置」只保存延后状态，不冒充完成；对话页和设置页可继续。未完成的步骤在重启后由真实状态重新判断。未保存的 Key、表单草稿、配对码和登录过程不会被保存为向导草稿。
- 完成是历史凭据，不是持续健康认证。完成后模型失效、QQ 掉线等仍由正常状态页处理，不反复强制首次向导。

## 2. 凭据来自哪里

`onboarding-store.js` 由 Main 独占 `onboarding.json`，只记版本、延后、本机/QQ 完成布尔、当前模型版本和密钥/路由摘要；无正文、原始账号、完整 Key。摘要不返回 Renderer。

Renderer 只有读状态、延后/继续、开始可选分支，没有「标记完成」或伪造模型结果的接口：

1. **模型测试**：Main 在请求前取当前已保存模型的版本和摘要；真实 Core 独立测试成功且版本仍匹配才记凭据。测试未保存草稿不认证当前设置；在途修改设置后，晚到的旧成功也不认证新设置。
2. **本机试聊**：经过正常聊天、审批和展示记录保存后，Main 才记录成功。不由向导自动发送，不吞掉最终回复，不把失败结果当完成。
3. **远程试聊**：Router 仅在模型正常完成、原渠道确认发送、账号仍在绑定表时发内部 `owner_reply` 元数据（渠道、模型版本、绑定哈希）。配对欢迎、系统错误回复、陌生人、发送失败、提醒都不算。事件不进入本机模型，不改变 external/local 隔离。

进度文件严格 schema、大小和文件类型检查；独占临时文件、fsync、rename，失败保留旧文件。成功动作后进度写失败时提示重新读取、不重复测试/发消息；同一个 Main 进程内的暂存凭据可在磁盘恢复后重试落盘，过期凭据丢弃。

**边界**：暂存凭据仅在内存。成功动作后、进度落盘前杀掉 Main，不能保证跨重启找回未知结果，也不承诺外部模型接口 exactly-once；重启后要明确核对账单/已有聊天，不能自动重测或重发。

## 3. 门禁与交互接线

- Main 未激活或未确认基础告知时不启动服务，也不探测 QQ 端口。有效许可证不等于已同意费用/数据告知。除激活、最小状态/关于、窗口控制与告知入口外，保护 IPC 还检查告知；Core 仍独立负责许可证验签，不能把 Main 的告知机制说成 Core 的额外权限系统。
- 激活后主页面在读取告知/向导状态前保持隐藏，避免闪现。风险确认只接受严格 true；重复进入会注销旧监听/续行，失败仍留在告知页。
- 模型表单复用 `model-view.js`，克隆控件全部 ID 与 aria 引用加前缀；清掉克隆的密码框，不碰正常设置页草稿。先保存才能测试，只保留一个主操作，不自动收费。
- 登录和配对复用既有入口，关闭时返回向导；重新读取实际状态，不用旧缓存误阻止刚启用的 QQ。远程暂停时提供显式恢复，不自动解除暂停。
- `main.js`、`preload.js`、`renderer.js` 三处已接；新增 `renderer/onboarding-view.js`。没有新 profile、工具或运行时许可证绕过开关。
