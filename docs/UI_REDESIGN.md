## 3. 框架接入方式

采用官方 shadcn/ui 的 Vite 接入方式与组件源代码，而不是照着它仿写一组 CSS：

- `renderer-src/App.tsx`：React 呈现壳。
- `renderer-src/components/ui/`：Button、Input、Textarea、Badge、NativeSelect 五种组件。附 MIT 许可、官方注册表来源及原始源码 SHA-256；仅适配本地工具函数、独立 Slot 包、自有下拉箭头。
- `renderer-src/shadcn.css`：Tailwind 本地构建入口，只扫描源码，避免把生成资源再次纳入扫描。
- `renderer/styles.css`：肥鱼布局、品牌 token 和安全状态的项目样式，不从 CDN 取资源。
- `scripts/build-ui.mjs`：生成 React 静态首帧、IIFE 客户端资源与 CSS。`renderer/index.html` 为生成文件，不能手改。
- `renderer-src/bootstrap.ts`：React 挂载完成后按原顺序启动九个既有控制器；同一启动 Promise 只执行一次。失败保留激活锁，不打开半挂载界面。

这是呈现层迁移，不是业务控制器重写。App 不引入运行时状态重渲染，字段无受控 value，动态区域由既有控制器管理；不使用 StrictMode 二次挂载。后续若要把某块改为 React 状态管理，须同步迁移该块控制器，不能让两边同时改 DOM。

首帧在 JavaScript 执行之前保持 `activation-locked`。React 不修改主进程/Core 独立验签。`contextIsolation: true`、`nodeIntegration: false` 和本地 CSP 保留。自定义审批/告知/激活/配对的业务处理没有换成框架自带的业务假实现。

### 命令与交付

```text
cd app/electron-ui
npm run check:ui
npm run build:ui
npm run framework-check
```

`npm start` / `npm run dev` 的前置脚本会先构建 UI，`pack` / `dist` 也先生成 UI；本轮只运行了 UI 资源编译，没有运行这四个会启动/打包的命令。双击开发入口目前消费已生成的本地资源，后续直接改源码时应先执行 build:ui。

React、构建工具及组件依赖精确锁定，仅作为开发依赖；运行资源打入 `renderer/assets/`，仍随既有 `renderer/**/*` 清单复制/打包，不依赖用户机器安装 React 或连接开发服务器。Electron 33.4.11、builder 25.1.8、Core 和第三方运行时未升级。

组件 MIT 许可与打入资源的依赖许可一同交付，见 `renderer/SHADCN_LICENSE.txt`、`renderer/THIRD_PARTY_NOTICES.txt`，包含相关 MIT/Apache 许可与 notice。
